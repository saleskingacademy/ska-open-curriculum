# Data Structures

> The course teaches applied data structures, including arrays, linked lists, and trees, assuming foundational knowledge of computer science concepts.

## Foundations

Data structures are systematic ways to organize, manage, and store data to enable efficient access and modification. At their core, data structures abstract the physical memory layout to provide logical models tailored to specific algorithmic needs. The foundational principle is balancing time complexity (access, insertion, deletion) against space complexity, often guided by the RAM model of computation. Key theoretical underpinnings include Big O notation for asymptotic analysis, locality of reference, and trade-offs between mutable and immutable representations. Data structures serve as the backbone for algorithms, enabling operations such as searching, sorting, indexing, and dynamic data manipulation. Their design is influenced by constraints like cache hierarchies, concurrency, and persistence.

In computer science, a data structure refers to a specific way of organizing and storing data in a computer so that it can be efficiently accessed, modified, and manipulated. A **computer** is an electronic device that can execute instructions, and **data** is the information that is being processed, which can be in the form of numbers, text, images, or other types of media. **Organization** of data refers to the way data is arranged and structured, which can be achieved through various data structures such as arrays, linked lists, stacks, queues, trees, and graphs. 
A **practitioner** is an individual who applies the principles of data structures to design, implement, and maintain software systems. **Core definitions** include the concept of **elements**, which are the individual items of data that are stored in a data structure, and **operations**, which are the actions that can be performed on the data structure, such as insertion, deletion, and searching. 
**First principles** of data structures include the trade-offs between **space complexity**, which refers to the amount of memory required to store the data, and **time complexity**, which refers to the amount of time required to perform operations on the data. Understanding these principles is crucial for designing efficient data structures and algorithms. 
Key vocabulary includes **algorithm**, which is a set of instructions that is used to solve a specific problem, and **data type**, which refers to the type of data being stored, such as integer, string, or boolean. A **variable** is a named location in memory that stores a value, and an **array** is a collection of elements of the same data type stored in contiguous memory locations.

For example, an algorithm with a time complexity of O(n) has a linear relationship between the input size and the time taken to execute. 
Understanding these core concepts is essential for designing, implementing, and analyzing data structures and algorithms in computer science.

## Arrays

Arrays are contiguous memory blocks storing elements of homogeneous type, enabling O(1) random access via index arithmetic: address = base_address + index * element_size. The canonical array supports fixed-size allocation, with dynamic arrays (e.g., C++ std::vector, Java ArrayList) implementing amortized O(1) append via geometric resizing—commonly doubling capacity when full, thus ensuring average insertion cost remains constant. Arrays underpin static lookup tables and matrix representations. Multi-dimensional arrays use row-major or column-major ordering, affecting cache performance and iteration strategies. Sparse arrays employ compressed storage (e.g., Compressed Sparse Row - CSR) to optimize memory for predominantly zero-valued data.

## Linked Lists

Linked lists are node-based dynamic data structures where each node contains data and one or more pointers to other nodes. The simplest singly linked list supports O(1) insertion/deletion at the head but O(n) search. Doubly linked lists add backward traversal pointers, facilitating O(1) deletions given a node reference. Variants include circular linked lists (tail node points to head), skip lists (multi-level linked lists enabling O(log n) search via probabilistic balancing), and XOR linked lists (memory-efficient by storing XOR of previous and next pointers). Linked lists excel in scenarios requiring frequent insertions/deletions without reallocations but suffer from poor cache locality.

## Trees

Trees are hierarchical, acyclic graphs with a designated root node. Binary trees restrict nodes to two children; binary search trees (BSTs) maintain the invariant left_child.key < node.key < right_child.key, enabling O(log n) average search, insertion, and deletion. Self-balancing variants—AVL trees (height-balanced with rotations maintaining O(log n) height) and Red-Black trees (color-coded nodes enforcing balanced black-height)—guarantee worst-case logarithmic operations. B-trees generalize to multi-way nodes, optimizing disk I/O by minimizing tree height, critical in databases and filesystems. Trie (prefix tree) structures index strings character-wise, enabling O(m) search for strings of length m, pivotal in autocomplete and IP routing.

## Hash Tables

Hash tables map keys to values via a hash function h(k), ideally distributing keys uniformly across buckets. Collision resolution strategies include chaining (linked lists or balanced trees per bucket) and open addressing (linear probing, quadratic probing, double hashing). The load factor α = n/m (n = number of elements, m = number of buckets) governs performance; maintaining α < 0.75 is standard to ensure average O(1) lookup. Cryptographic or universal hash functions minimize collisions and adversarial attacks. Dynamic resizing (rehashing) occurs when α exceeds thresholds, doubling bucket count and redistributing entries. Cuckoo hashing uses two hash functions and constant worst-case lookup by relocating keys, trading off insertion complexity.

## Graphs

Graphs G = (V, E) represent pairwise relationships with vertices V and edges E, either directed or undirected, weighted or unweighted. Representations include adjacency matrices (O(|V|^2) space, O(1) edge queries) and adjacency lists (O(|V| + |E|) space, efficient for sparse graphs). Specialized structures include incidence lists and edge lists. Algorithms leverage these structures: Dijkstra’s algorithm for shortest paths uses priority queues and adjacency lists; Bellman-Ford handles negative weights; Tarjan’s algorithm identifies strongly connected components via DFS and low-link values. Graph traversals—DFS and BFS—operate in O(|V| + |E|) time, foundational for connectivity, cycle detection, and topological sorting.

## Heaps And Priority Queues

Heaps are specialized tree-based data structures satisfying the heap property: in max-heaps, each parent node ≥ children; in min-heaps, ≤ children. Binary heaps support O(log n) insertion and extraction of the extreme element, implemented as arrays with parent/child index relations (parent(i) = floor((i-1)/2)). Fibonacci heaps improve amortized complexities: O(1) insert and decrease-key, O(log n) extract-min, critical in advanced algorithms like Dijkstra’s. Binomial heaps organize trees of increasing order for efficient merges. Priority queues abstract these structures, enabling task scheduling, event simulation, and graph algorithms.

## Matrix And Tensor Structures

Matrices are 2D arrays with operations defined by linear algebra; sparse matrices use formats like CSR, CSC, and COO to store only nonzero elements, reducing memory and computation. Tensor data structures generalize matrices to higher dimensions, essential in machine learning and scientific computing. Efficient tensor storage exploits sparsity patterns and symmetries. Block matrices partition large matrices into submatrices, optimizing cache usage and parallelism. Operations include matrix multiplication (O(n^3) naive, Strassen’s algorithm O(n^2.81)), decomposition (LU, QR, SVD), and inversion, each relying on underlying data structures for performance.

## Mechanisms

In computer science, data structures are implemented using various mechanisms that enable efficient storage, retrieval, and manipulation of data. The primary mechanism involves the use of pointers, which are variables that store memory addresses of other variables. This allows for dynamic memory allocation, where memory is allocated or deallocated as needed. The causal chain begins with the declaration of a data structure, such as an array or linked list, which reserves a contiguous block of memory or a sequence of non-contiguous blocks. When data is inserted or deleted, the pointers are updated to reflect the new memory layout, ensuring that the data structure remains consistent. The operating system plays a crucial role in managing memory allocation and deallocation, using mechanisms such as paging and segmentation to optimize memory usage. Additionally, algorithms such as hashing and indexing are used to facilitate efficient data retrieval and manipulation. The step-by-step process involves the initialization of the data structure, followed by the insertion or deletion of data, and finally, the updating of pointers and memory allocation to maintain data consistency. This complex interplay of mechanisms enables data structures to provide efficient and organized access to data, which is essential for a wide range of computer science applications.

## Methods And Frameworks

In computer science, various methods and frameworks are employed to design, implement, and analyze data structures. The Big O notation is a method used to describe the time and space complexity of algorithms, helping to predict their performance. Divide and Conquer is a framework used to solve complex problems by breaking them down into smaller sub-problems, such as in merge sort and binary search. Dynamic Programming is a method used to solve problems by breaking them down into smaller sub-problems and storing the solutions to sub-problems to avoid redundant computation, as seen in the Fibonacci sequence and shortest paths problems. 
The Master Theorem is a formula used to solve recurrence relations, which describe the time complexity of recursive algorithms. It is applicable when the recurrence relation has a specific form, but fails when the relation is too complex or has multiple recursive calls. 
Hashing is a method used for efficient storage and retrieval of data, but its failure mode is collision, which occurs when two different keys produce the same hash value. 
Greedy algorithms are a framework used to solve problems by making locally optimal choices, but they fail when the locally optimal choice does not lead to a globally optimal solution, as seen in the Knapsack problem. 
Recursion is a method used to solve problems by breaking them down into smaller instances of the same problem, but its failure mode is stack overflow, which occurs when the recursive calls exceed the maximum stack size.

## Worked Examples

To illustrate the application of data structures, consider the following examples. 
1. **Array Indexing**: Given an array of integers `A = [5, 10, 15, 20, 25]`, find the value at index 3. In most programming languages, arrays are 0-indexed, meaning the first element is at index 0. Therefore, the value at index 3 is `A[3] = 20`. 
2. **Stack Operations**: A stack is a Last-In-First-Out (LIFO) data structure. Suppose we have a stack `S` with initial elements `[1, 2, 3]`. If we push the element `4` onto the stack, it becomes `[1, 2, 3, 4]`. Then, if we pop an element from the stack, we get `4` and the stack becomes `[1, 2, 3]`. 
3. **Binary Search**: Given a sorted array `B = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]`, find the index of the element `23` using binary search. Start by finding the middle index `mid = (0 + 9) / 2 = 4`. Compare the middle element `B[4] = 16` with the target `23`. Since `23 > 16`, repeat the process on the right half of the array. The new middle index is `mid = (5 + 9) / 2 = 7`. Compare `B[7] = 56` with `23`. Since `23 < 56`, repeat the process on the left half of the right half. The new middle index is `mid = (5 + 6) / 2 = 5`. Compare `B[5] = 23` with `23`. Since they are equal, the index of `23` is `5`.

1. **Stack Implementation**: Suppose we want to implement a stack using an array to store the elements. If we have an array of size 5 and we push the elements 10, 20, 30, 40, and 50 onto the stack, the array will be filled. If we then pop two elements, the top two elements (50 and 40) will be removed, leaving us with 10, 20, and 30 in the array.

     / \    /
    4   7  13
If we perform an in-order traversal of this tree, we will visit the nodes in the following order: 1, 3, 4, 6, 7, 8, 10, 13, 14. 
3. **Hash Table Collision Resolution**: Suppose we have a hash table with 10 slots and we use the modulo operator to map keys to slots. If we insert the keys 12, 22, 32, and 42, they will all map to slot 2 (12 mod 10 = 2, 22 mod 10 = 2, etc.). To resolve this collision, we can use chaining, where each slot contains a linked list of colliding elements. In this case, the linked list at slot 2 will contain the keys 12, 22, 32, and 42.

## Applications

Data structures are fundamental components in various computer science applications, including database management systems, file systems, and web search engines. In database management systems, data structures such as B-trees and hash tables are used to index and retrieve data efficiently. For instance, B-trees are self-balancing search trees that allow for efficient insertion, deletion, and search operations, making them suitable for large-scale databases. In file systems, data structures like linked lists and trees are used to manage files and directories, enabling efficient creation, deletion, and navigation of files. Web search engines rely on data structures such as inverted indexes and graph data structures to index web pages and rank search results. Additionally, data structures like stacks and queues are used in compiler design to parse syntax and manage memory, while heaps and priority queues are used in scheduling algorithms to manage system resources. The choice of data structure depends on the specific requirements of the application, including factors such as data size, access patterns, and performance constraints.

## Common Errors

In the implementation and utilization of data structures, practitioners often make mistakes that can lead to inefficiencies, errors, or even program crashes. One common error is the incorrect handling of edge cases, such as null or empty inputs, when working with data structures like linked lists or trees. For instance, failing to check for a null pointer before traversing a linked list can result in a null pointer exception. Another mistake is the misuse of data structure operations, like attempting to access an element out of bounds in an array or trying to insert a duplicate key into a hash table that does not support duplicates. Additionally, practitioners may overlook the importance of considering the time and space complexity of data structure operations, leading to inefficient algorithms. For example, using a linear search on a large dataset instead of a more efficient search algorithm like binary search can significantly impact performance. Furthermore, not properly synchronizing access to shared data structures in multi-threaded environments can lead to concurrency issues and data corruption. These errors often stem from a lack of understanding of the underlying data structure principles or a failure to consider the specific requirements and constraints of the problem at hand.
