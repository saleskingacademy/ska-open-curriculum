# Vue

> The course assumes prior knowledge of JavaScript and web development fundamentals, but focuses on applying Vue.js principles to real situations.

## Foundations

Vue.js is a progressive JavaScript framework for building user interfaces, primarily focusing on the view layer (MVVM pattern). At its core, Vue operates on a reactive data-binding system, employing a Virtual DOM diffing algorithm for efficient UI updates. Vue’s design principles emphasize declarative rendering, component-based architecture, and an incrementally adoptable ecosystem. The framework leverages a reactive dependency-tracking system via ES5 getters/setters (Vue 2) or Proxies (Vue 3) to detect data changes and trigger view updates. Vue’s template syntax compiles to render functions, which produce Virtual DOM nodes, enabling fine-grained reactivity and optimized patching. Vue 3 introduces the Composition API, enabling function-based logic reuse and improved TypeScript integration, while maintaining backward compatibility with the Options API.

## Reactivity System

Vue’s reactivity is implemented through reactive effect tracking and dependency collection. In Vue 2, Object.defineProperty intercepts property access and mutations, registering dependencies during getter calls and triggering effects in setters. Vue 3 replaces this with ES6 Proxy, enabling full object observation without property enumeration limitations. Core APIs include `reactive()`, which converts an object into a reactive proxy; `ref()`, which creates a reactive primitive wrapper; and `computed()`, which caches derived reactive values. The scheduler batches changes asynchronously using microtasks (Promise.then) to optimize DOM updates. The dependency graph is maintained via `effect()` functions, which track reactive sources and re-run on mutation, ensuring minimal recomputation.

## Template Syntax & Directives

Vue templates use an HTML-based syntax extended with directives that bind DOM elements to reactive data. Key directives include `v-bind` for attribute binding, `v-model` for two-way data binding, `v-if`/`v-else-if`/`v-else` for conditional rendering, `v-for` for list rendering with keyed nodes, and event listeners via `v-on`. Directives compile into render functions that create Virtual DOM nodes with embedded reactive bindings. Template expressions support JavaScript expressions but exclude statements, promoting declarative logic. Scoped slots and named slots enable flexible component composition and content distribution.

## Components & Lifecycle

Vue components encapsulate UI elements with isolated state, props, and lifecycle hooks. Components are defined via the Options API (`data()`, `props`, `methods`, `computed`, `watch`, lifecycle hooks like `created()`, `mounted()`) or the Composition API (setup function returning reactive state and methods). The component lifecycle includes: `beforeCreate`, `created`, `beforeMount`, `mounted`, `beforeUpdate`, `updated`, `beforeUnmount`, and `unmounted`. Components communicate via props (parent-to-child) and custom events (`$emit`) for child-to-parent. Provide/inject enables dependency injection for deep component trees. Async components and dynamic async imports optimize bundle size and load time.

## Composition Api & Logic Reuse

Introduced in Vue 3, the Composition API enables organizing component logic by feature rather than by options type. The `setup()` function is the entry point, receiving props and context, returning reactive state and methods. Core Composition API functions include `reactive()`, `ref()`, `computed()`, `watch()`, `watchEffect()`, and lifecycle hooks (`onMounted`, `onUnmounted`). Custom composables are reusable functions encapsulating reactive logic, promoting code modularity and testability. This API integrates seamlessly with TypeScript, providing strong typing and inference. It supports advanced patterns like reactive stores, cross-cutting concerns, and side-effect management.

## State Management With Vuex & Pinia

Vuex is Vue’s official centralized state management library based on Flux architecture. It uses a single store with state, mutations (synchronous state changes), actions (async operations), getters (computed state), and modules for scalability. Vuex enforces strict unidirectional data flow and immutability principles. Pinia, the modern alternative, offers a simpler API with modular stores, direct state mutation, and better TypeScript support. Pinia stores are defined via `defineStore()`, exposing state, getters, and actions as plain functions and reactive properties. Both integrate with devtools for time-travel debugging and state snapshots.

## Routing With Vue Router

Vue Router manages SPA navigation with declarative route definitions and dynamic routing. Routes are defined as objects with `path`, `component`, `children`, `props`, and meta fields. It supports dynamic segments (`:id`), nested routes, named views, and navigation guards (`beforeEach`, `beforeResolve`, `afterEach`) for authentication and side effects. Route params and query strings are reactive via `useRoute()`. Programmatic navigation uses `router.push()`, `router.replace()`. Vue Router supports history modes: hash (`#/path`) and HTML5 history API (`/path`), with fallback and scroll behavior control.

## Performance Optimizations

Vue optimizes rendering via Virtual DOM diffing with heuristics to minimize patches. Key optimizations include keyed `v-for` lists to preserve element identity, `v-once` for static content, and `v-memo` (Vue 3.3+) to memoize subtrees. Lazy loading components with dynamic imports and code splitting reduces initial bundle size. Suspense components handle asynchronous dependencies gracefully. The compiler performs static tree hoisting and patch flag generation to optimize runtime updates. Developers can leverage `shallowReactive()` and `markRaw()` to fine-tune reactivity overhead. Devtools provide performance profiling and component render tracking.

## Mechanisms

Vue's core mechanisms involve a combination of reactive components, a virtual DOM, and a component-based architecture. The process begins with the creation of a Vue instance, which initializes the application and sets up the necessary event listeners. When the state of a component changes, Vue's reactivity system is triggered, causing the component to re-render. This re-rendering process involves the creation of a new virtual DOM, which is a lightweight in-memory representation of the actual DOM. The virtual DOM is then compared to the previous virtual DOM, and the differences are computed. These differences are used to update the actual DOM, ensuring that only the necessary changes are made, resulting in efficient and optimized rendering. The component-based architecture allows for a modular and reusable approach to building applications, with each component managing its own state and behavior. The causal chain is as follows: state change -> reactivity system triggered -> component re-rendered -> new virtual DOM created -> virtual DOM compared to previous virtual DOM -> differences computed -> actual DOM updated. This process enables Vue to efficiently and effectively manage complex user interfaces and applications.

## Methods And Frameworks

In Vue, several methods and frameworks facilitate efficient application development. The Model-View-ViewModel (MVVM) pattern is a key framework, separating the application logic into three interconnected components. The Vue Router is used for client-side routing, allowing for seamless navigation between views. The Vuex state management pattern is utilized for managing global state by providing a single source of truth for state. 
The computed properties method is used for caching and optimizing derived data, while watchers are used for observing and reacting to changes in specific data properties. 
When to use: Computed properties are ideal for complex calculations, whereas watchers are suitable for handling asynchronous operations or API calls. 
Failure mode: Incorrect usage of computed properties can lead to infinite loops or unnecessary computations, while misuse of watchers can result in memory leaks or slow performance. 
Additionally, Vue's lifecycle hooks, such as mounted, updated, and destroyed, provide a way to execute code at specific points in a component's lifecycle. 
When to use: Lifecycle hooks are essential for initializing or cleaning up resources, such as DOM elements or API connections. 
Failure mode: Failing to properly clean up resources in the destroyed hook can cause memory leaks, while incorrect usage of the mounted hook can lead to premature execution of code. 
Understanding these methods and frameworks is crucial for building scalable, maintainable, and efficient Vue applications.

## Worked Examples

To illustrate the application of Vue in computer science, consider the following examples. 
1. **Todo List App**: Suppose we want to build a Todo List App using Vue. We start by creating a new Vue instance and defining the data, template, and methods. For instance, `new Vue({ data: { todos: [] }, template: '<ul><li v-for="todo in todos">{{ todo }}</li></ul>', methods: { addTodo: function() { this.todos.push('New Todo') } } })`. This example demonstrates how to create a simple Vue application with dynamic data and user interaction.
2. **Component-Based Architecture**: Consider a Vue application with a component-based architecture, where we have a parent component and a child component. The parent component passes data to the child component using props. For example, `<template><div><child :msg="message"></child></div></template>`, where `message` is a property of the parent component. This example illustrates how to implement a component-based architecture in Vue.
3. **State Management with Vuex**: Suppose we want to manage the state of a Vue application using Vuex. We create a Vuex store and define the state, mutations, and actions. For instance, `const store = new Vuex.Store({ state: { count: 0 }, mutations: { increment(state) { state.count++ } }, actions: { increment(context) { context.commit('increment') } } })`. This example demonstrates how to use Vuex to manage the state of a Vue application.

## Common Errors

In Vue, common errors often stem from misunderstandings of its reactive components and lifecycle hooks. One mistake is incorrectly using the `v-if` and `v-for` directives together on the same element, which can lead to unexpected behavior. This is because `v-for` has a higher priority than `v-if`, so the loop will be executed before the conditional, potentially causing the component to render unnecessarily. Another error is failing to use the `key` attribute in `v-for` loops, which can cause Vue to reuse existing DOM elements instead of creating new ones, leading to incorrect rendering and potential bugs. Additionally, not properly handling asynchronous data fetching in the `created` or `mounted` lifecycle hooks can result in components attempting to render before data is available, causing errors. Furthermore, misuse of the `this` keyword in Vue's single-file components can lead to issues with accessing component properties and methods, as the context of `this` can change depending on the function being called. Understanding the nuances of Vue's reactivity system and carefully managing component state and lifecycle methods are crucial to avoiding these common pitfalls.
