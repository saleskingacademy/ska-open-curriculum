# Operating Systems

> The course assumes prior knowledge of computer science fundamentals and dives into the application of operating system principles.

## Foundations

An operating system (OS) is a privileged software layer that abstracts and manages hardware resources, providing a controlled execution environment for user applications. At its core, the OS enforces the principle of resource multiplexing, ensuring safe, efficient, and fair sharing of CPU, memory, I/O devices, and storage. The foundational abstractions include processes (active computation units), files (persistent data abstractions), and virtual memory (illusion of large, contiguous address spaces). The OS mediates between hardware and software via system calls, interrupts, and privileged instructions, implementing protection, concurrency, and persistence. Key first principles include separation of mechanism and policy, minimal trusted computing base, and layered design.

In the context of computer science, an Operating System (OS) is a software component that manages computer hardware resources and provides a platform for running application software. A **computer system** consists of hardware and software components, where **hardware** refers to the physical components such as the Central Processing Unit (CPU), memory, and input/output devices, and **software** refers to the programs and operating systems that run on the hardware. The OS acts as an intermediary between computer hardware and user-level applications, controlling the allocation of system resources such as **memory** (temporary storage for data), **CPU time** (processing capacity), and **input/output devices** (e.g., keyboards, displays). Key concepts in OS design include **processes** (programs in execution), **threads** (lightweight processes), and **synchronization** (coordinating access to shared resources). A **kernel** is the core part of an OS, responsible for managing the system's hardware resources and providing basic services to applications. Understanding these core definitions and principles is essential for designing, implementing, and interacting with operating systems.

## Process Management

Framework: Process Control Block (PCB) and Scheduling Algorithms  
Each process is represented by a PCB containing PID, CPU registers, program counter, memory maps, open files, and state (new, ready, running, waiting, terminated). The OS scheduler applies algorithms such as:  
- Round Robin (time quantum q, typically 10–100 ms) for fairness  
- Multilevel Feedback Queue (MLFQ) with dynamic priority adjustment based on CPU bursts  
- Completely Fair Scheduler (CFS) using a red-black tree to approximate ideal processor sharing, with vruntime as the key metric  
Context switch overhead is minimized by saving/restoring PCB registers and TLB flushes. Preemptive multitasking is driven by timer interrupts (e.g., PIT at 100 Hz). Real-time OSes employ Rate Monotonic Scheduling (RMS) or Earliest Deadline First (EDF) for deterministic guarantees.

## Memory Management

Framework: Paging and Segmentation with Virtual Memory  
Virtual memory abstracts physical RAM via page tables mapping virtual addresses to physical frames, typically 4KB pages on x86 architectures. The OS uses a hierarchical page table (e.g., 4-level in x86_64) or inverted page tables to optimize lookup. Translation Lookaside Buffers (TLBs) cache recent translations to reduce latency. Demand paging loads pages on fault (page fault handler), with replacement policies like Least Recently Used (LRU) approximated via Clock algorithm. Segmentation provides logical division (code, data, stack) with base and limit registers, though largely superseded by paging. Memory protection is enforced via page table entry flags (read/write/execute). Swapping moves inactive pages to disk-backed swap space to extend apparent RAM.

## File Systems

Framework: Inode-based Hierarchical File System with Journaling  
Files are represented by inodes containing metadata (size, timestamps, permissions, block pointers). The OS uses directory structures as tree or DAGs mapping names to inode numbers. Common file systems include ext4 (Linux), NTFS (Windows), and APFS (macOS). Journaling (e.g., write-ahead logging) ensures consistency by recording intent before data writes, enabling crash recovery. Allocation strategies include contiguous, linked, and indexed allocation (extents). File caching and buffering optimize I/O throughput. Permissions are enforced via Access Control Lists (ACLs) or POSIX mode bits. Mounting integrates disparate file systems into a unified namespace.

## Interrupts And I/O Management

Framework: Interrupt Descriptor Table (IDT) and Device Driver Model  
The OS uses an IDT to map interrupt vectors to handler routines. Hardware interrupts (IRQs) signal device events; software interrupts (syscalls) request OS services. Interrupt handling involves saving CPU state, executing the handler, and signaling end-of-interrupt (EOI) to the Programmable Interrupt Controller (PIC) or Advanced Programmable Interrupt Controller (APIC). Device drivers abstract hardware specifics, exposing uniform interfaces (block, character, network devices). Direct Memory Access (DMA) allows devices to transfer data to/from memory without CPU intervention, improving throughput. Polling and interrupt-driven I/O balance latency and overhead. The OS manages buffers, queues, and synchronization primitives (spinlocks, semaphores) to coordinate concurrent access.

## Concurrency And Synchronization

Framework: Locks, Semaphores, Monitors, and Deadlock Handling  
Concurrency control uses primitives:  
- Spinlocks for short, busy-wait critical sections  
- Binary and counting semaphores for signaling and resource counting  
- Monitors encapsulating mutual exclusion and condition variables  
Deadlock conditions (Coffman’s four: mutual exclusion, hold and wait, no preemption, circular wait) are addressed via prevention (ordering resources), avoidance (Banker’s algorithm), detection (wait-for graph), and recovery (process termination or resource preemption). Memory models and atomic operations (compare-and-swap, test-and-set) underpin lock-free and wait-free algorithms. Thread scheduling may involve priority inheritance to avoid priority inversion.

## Virtualization And Containers

Framework: Hypervisor Types and Namespace Isolation  
Type 1 hypervisors (bare-metal, e.g., Xen, VMware ESXi) run directly on hardware, managing guest OSes with full virtualization or paravirtualization. Type 2 hypervisors (hosted, e.g., VirtualBox) run atop a host OS. Hardware-assisted virtualization (Intel VT-x, AMD-V) enables efficient guest context switches and memory virtualization via Extended Page Tables (EPT). Containers (e.g., Docker) leverage OS-level virtualization using namespaces (PID, mount, network) and cgroups for resource isolation and control without full guest OS overhead. This enables lightweight, scalable deployment with near-native performance.

## Security And Protection

Framework: Access Control Models and Kernel/User Mode Separation  
The OS enforces security via access control lists (ACLs), capabilities, and mandatory access control (MAC) frameworks like SELinux or AppArmor. Kernel mode (ring 0) has unrestricted hardware access; user mode (ring 3) is restricted, with transitions via syscalls or exceptions. Address space layout randomization (ASLR) and Data Execution Prevention (DEP) mitigate exploitation. Secure boot and Trusted Platform Module (TPM) integration ensure boot integrity. Sandboxing and virtualization provide containment. Formal verification and microkernel architectures (e.g., seL4) aim to minimize trusted computing base and reduce vulnerabilities.

## Mechanisms

The operating system (OS) manages computer hardware resources and provides a platform for running application software. The OS achieves this through several key mechanisms. The boot process initiates the OS, where the bootloader loads the OS kernel into memory. The kernel then initializes hardware components and sets up the memory management unit (MMU) to manage virtual memory. The OS creates a process by allocating memory, assigning a unique process ID, and initializing the program counter. The scheduler selects the next process to run based on priority and availability, using algorithms such as First-Come-First-Served (FCFS) or Round Robin (RR). Context switching occurs when the scheduler switches between processes, saving the current state of the outgoing process and restoring the saved state of the incoming process. Interrupt handling allows the OS to respond to hardware events, such as keyboard input or disk completion, by executing interrupt service routines (ISRs). The OS also manages memory through pagination or segmentation, ensuring efficient use of physical memory and preventing memory conflicts between processes. File systems, such as FAT or NTFS, provide a hierarchical structure for storing and retrieving files, while device drivers manage input/output operations between the OS and hardware devices. These mechanisms work together to provide a functional and efficient computing environment.

The interrupt mechanism allows hardware devices to signal the CPU, triggering an interrupt handler to handle the event. The context switch mechanism enables the OS to switch between processes, saving and restoring register states and memory maps. The scheduling mechanism allocates CPU time to processes, using algorithms like First-Come-First-Served (FCFS), Shortest Job First (SJF), or Priority Scheduling. The memory management mechanism virtualizes memory, using paging or segmentation to map virtual addresses to physical addresses. The file system mechanism provides a hierarchical storage structure, using inode or file allocation table (FAT) based systems to manage files and directories. The input/output (I/O) mechanism manages data transfer between devices and memory, using device drivers and buffers to optimize performance. These mechanisms interact through a causal chain, where the kernel receives interrupts, schedules processes, allocates memory, and performs I/O operations to provide services to applications.

## Methods And Frameworks

In operating system design, several methods and frameworks are employed to manage system resources, ensure efficiency, and prevent errors. The Banker's Algorithm is used for deadlock avoidance, where it tests for safe states to prevent deadlocks. It is applied when the maximum resources available and the maximum resources that can be requested by each process are known. Failure mode occurs when the algorithm is unable to find a safe sequence, leading to system instability. 
The Rate Monotonic Scheduling (RMS) framework is used for real-time systems, allocating priorities based on the period of each task. It is applied when task periods and deadlines are fixed and known. Failure mode occurs when tasks have varying periods or priorities, leading to missed deadlines. 
The Thread-Per-Connection model is used for concurrent server design, where each incoming connection is handled by a separate thread. It is applied when the number of connections is relatively low and each connection requires minimal processing. Failure mode occurs when the number of connections is high, leading to thread overhead and decreased system performance. 
The Producer-Consumer problem is solved using the Semaphores method, which coordinates access to shared resources. It is applied when multiple processes share a common buffer. Failure mode occurs when semaphore operations are not atomic, leading to data inconsistency. 
The Master-Slave framework is used for distributed systems, where one process (master) controls multiple processes (slaves). It is applied when tasks can be divided into smaller sub-tasks. Failure mode occurs when the master process fails, leading to system failure.

This formula is suitable for systems with a steady-state arrival rate, but it may fail if the system has a variable arrival rate or if the task durations are highly variable.

## Worked Examples

To illustrate key concepts in operating systems, consider the following examples. 
1. **Process Scheduling**: Suppose we have three processes with burst times of 10ms, 5ms, and 8ms, and arrival times of 0ms, 3ms, and 6ms, respectively. Using the First-Come-First-Served (FCFS) scheduling algorithm, the total waiting time and turnaround time can be calculated. The waiting time for each process would be 0ms, 10ms, and 15ms, and the turnaround times would be 10ms, 15ms, and 23ms. 
2. **Memory Management**: A system has 64MB of physical memory and uses paging with a page size of 4KB. If a process requires 20MB of memory, how many pages will it occupy? Since each page is 4KB (4096 bytes), the number of pages required is 20MB / 4KB = 20 * 1024 * 1024 / 4096 = 5120 pages.
3. **Disk Scheduling**: Consider a disk with a total of 100 cylinders, and pending requests at cylinders 10, 30, 50, 70, and 90. Using the Shortest-Seek-Time-First (SSTF) algorithm, starting from the current head position at cylinder 40, the order of servicing would be 50, 70, 90, 30, and 10, resulting in a total head movement of 10 + 20 + 20 + 40 + 40 = 130 cylinders.

## Applications

Operating systems are used in various domains, including desktop computing, mobile devices, servers, and embedded systems. In desktop computing, operating systems such as Windows, macOS, and Linux manage hardware resources, provide a platform for running applications, and offer services like file management, networking, and security. Mobile devices, such as smartphones and tablets, rely on operating systems like Android and iOS to manage touch input, battery life, and wireless connectivity. Server operating systems, including Windows Server and Linux distributions, support multi-user environments, manage network resources, and provide services like web hosting and database management. Embedded systems, found in devices like traffic lights, appliances, and automotive systems, utilize specialized operating systems like VxWorks and FreeRTOS to manage real-time operations, optimize resource usage, and ensure reliability. Additionally, operating systems play a crucial role in cloud computing, where they manage virtual machines, allocate resources, and provide scalability and fault tolerance. The choice of operating system depends on the specific requirements of the application, including performance, security, and compatibility considerations.

## Common Errors

In operating system design and implementation, several common errors can lead to system instability, security vulnerabilities, and performance degradation. One such error is the incorrect use of synchronization primitives, such as locks and semaphores, which can result in deadlock or livelock situations. Deadlock occurs when two or more processes are blocked indefinitely, each waiting for the other to release a resource, while livelock is a situation where two or more processes are unable to proceed because they are too busy responding to each other's actions. Another common error is the failure to handle interrupts and exceptions properly, which can cause the system to crash or become unresponsive. Additionally, incorrect memory management, such as dangling pointers or buffer overflows, can lead to memory corruption and security vulnerabilities. Practitioners may also make errors in process scheduling, such as priority inversion, where a higher-priority process is blocked by a lower-priority process, leading to decreased system responsiveness. Furthermore, errors in file system management, such as incorrect handling of file descriptors or permissions, can result in data loss or security breaches. These errors can be avoided by following best practices, such as using established synchronization algorithms, handling interrupts and exceptions properly, and implementing robust memory management and process scheduling mechanisms.

These errors can be mitigated by following established design principles, testing thoroughly, and using proven technologies and methodologies.

## Advanced

In advanced operating systems research, several key areas are being explored, including novel memory management techniques, such as software-based memory virtualization and hardware-assisted memory management. Another area of focus is on energy-aware and power-efficient operating systems, which aim to minimize energy consumption while maintaining performance. The rise of cloud computing and edge computing has also led to research on distributed and decentralized operating systems, which can efficiently manage resources across multiple machines and locations. Furthermore, the increasing use of artificial intelligence and machine learning in operating systems is driving the development of self-healing, self-optimizing, and autonomous systems. Researchers are also exploring the use of programming languages and compilers to generate operating system code, allowing for more efficient and secure systems. Overall, the field of operating systems is evolving to address the challenges of emerging technologies and applications, while maintaining the core principles of efficiency, security, and reliability.
