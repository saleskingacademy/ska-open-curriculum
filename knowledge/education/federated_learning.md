# Federated Learning

> The course teaches core principles and mechanisms of federated learning, assuming some basic knowledge of machine learning concepts.

## Foundations

Federated learning is a machine learning approach that enables multiple actors, referred to as clients or nodes, to collaboratively train a model while maintaining the data private on each client's device. **Decentralization** is a core principle, where data is not transmitted to a central server, but rather, the model is shared and updated across clients. A **client** is an entity that holds a dataset and participates in the federated learning process, which can be a mobile device, organization, or any other data owner. 
The **server** is the central component that orchestrates the federated learning process, responsible for aggregating and updating the shared model. **Model aggregation** refers to the process of combining the updates from multiple clients to form a new, shared model. 
Key concepts include **data privacy**, which ensures that client data is not exposed during the learning process, and **non-iid** (non-identically and independently distributed) data, which acknowledges that client data distributions may differ. 
Federated learning algorithms must account for **communication efficiency**, balancing the trade-off between model accuracy and the number of updates transmitted between clients and the server. 
Understanding these foundational concepts is crucial for designing and implementing effective federated learning systems.

A **client** is an entity that holds a portion of the data and participates in the federated learning process. **Local data** refers to the data stored on each client, which is not shared with other clients or a central server. 
In contrast, a **central server** or **aggregator** is responsible for coordinating the federated learning process, aggregating updates from clients, and broadcasting the updated global model. The **global model** is the shared model that is trained collaboratively by all clients. **Model updates** are the changes made to the global model by each client, typically in the form of model weights or gradients. 
Federated learning relies on **iterative optimization**, where clients iteratively update the global model by minimizing a **loss function**, which measures the difference between the model's predictions and the actual outputs. The **federated averaging algorithm** is a common approach used to aggregate model updates from clients, which involves averaging the model weights or gradients to update the global model. 
Understanding these core definitions and principles is essential for a practitioner to design and implement effective federated learning systems.

## Mechanisms

Federated learning operates through a decentralized architecture, where multiple actors, typically referred to as clients or nodes, collaborate to train a shared model without directly sharing their data. The process unfolds as follows: 
1. **Initialization**: A central server, often referred to as the aggregator, initializes a global model. This model serves as the starting point for the federated learning process.
2. **Client Selection**: The aggregator selects a subset of clients to participate in the current round of training. The selection criteria can vary, including random selection, availability, or specific client characteristics.
3. **Local Model Training**: Each selected client receives the current global model and updates it using its local data. The update process involves training the model on the client's private data, which results in a local model.
4. **Gradient or Model Update**: Clients compute updates to the model, typically in the form of gradients or the updated model itself, based on their local training. These updates are then shared with the aggregator.
5. **Aggregation**: The aggregator collects updates from all participating clients and combines them to update the global model. This is often done using a weighted average, where the weights reflect the contribution or trustworthiness of each client.
6. **Global Model Update**: The updated global model is computed by incorporating the aggregated updates into the previous global model.
7. **Model Broadcast**: The new global model is broadcast back to the clients, replacing their previous versions. This updated model serves as the basis for the next round of local training.
8. **Iteration**: Steps 2 through 7 are repeated for multiple rounds, with the global model iteratively improving as it learns from the collective data of all clients without directly accessing their private data.
This iterative process allows federated learning to achieve a shared, accurate model while preserving the privacy of client data, a key principle in its design.

## Methods And Frameworks

Federated learning employs various methods and frameworks to facilitate collaborative model training while maintaining data privacy. 
1. **FedAvg**: a widely used algorithm that averages local model updates, suitable for homogeneous data distributions. Failure mode: biased towards clients with larger datasets.
2. **FedProx**: an extension of FedAvg, incorporating proximal terms to handle non-IID data, suitable for heterogeneous environments. Failure mode: sensitive to hyperparameter tuning.
3. **Differential Privacy (DP)**: a framework ensuring client data privacy by adding noise to local updates, suitable for sensitive data applications. Failure mode: potential decrease in model accuracy due to added noise.
4. **Secure Multi-Party Computation (SMPC)**: a framework enabling secure collaborative computation, suitable for high-stakes applications. Failure mode: high computational overhead and potential scalability issues.
5. **Hierarchical Federated Learning (HFL)**: a framework organizing clients in a hierarchical structure, suitable for large-scale deployments. Failure mode: increased communication complexity and potential bottlenecks.
When selecting a method or framework, consider factors such as data distribution, client heterogeneity, and privacy requirements to ensure optimal performance and minimize potential failure modes.

## Applications

Federated learning has numerous applications in practice, particularly in domains where data is decentralized, sensitive, or has privacy concerns. In healthcare, federated learning enables the training of machine learning models on electronic health records (EHRs) across multiple hospitals or institutions without sharing patient data, thus preserving patient confidentiality. For instance, a federated learning model can be trained to predict patient outcomes or diagnose diseases using EHRs from various hospitals, improving model accuracy and generalizability. 
In the financial sector, federated learning can be applied to detect fraudulent transactions or predict credit risk by training models on transaction data from multiple banks or financial institutions, while maintaining data privacy and security. 
Additionally, federated learning is used in edge computing, such as in smart homes or cities, where devices like sensors and cameras generate vast amounts of data that can be used to train models for tasks like anomaly detection or predictive maintenance, without needing to transmit data to a central server. 
In autonomous vehicles, federated learning can be employed to improve vehicle safety by training models on data from multiple vehicles, enabling them to learn from each other's experiences and adapt to new environments. 
These applications demonstrate the potential of federated learning to enable machine learning in decentralized and privacy-sensitive environments, highlighting its importance in various domains.

## Common Errors

In federated learning, practitioners often make mistakes that compromise the performance, security, and fairness of the model. One common error is assuming that local models will converge to a global optimum without proper regularization techniques, leading to overfitting to local data distributions. Another mistake is neglecting to account for non-IID (independent and identically distributed) data, where local datasets have different statistical properties, resulting in biased global models. Additionally, some practitioners fail to implement robust aggregation methods, such as median or trimmed mean, making the global model vulnerable to outliers or adversarial attacks. Furthermore, inadequate handling of client drift, where local data distributions change over time, can cause the global model to become stale and perform poorly. Ignoring the importance of differential privacy and secure multi-party computation can also lead to privacy breaches and exposure of sensitive client data. Lastly, some practitioners overlook the need for careful hyperparameter tuning and model selection, which can significantly impact the performance of the federated learning system. These errors can be mitigated by understanding the fundamental principles of federated learning, including data heterogeneity, client privacy, and model aggregation.
