# Zero Knowledge Proofs

> The course assumes basic knowledge of discrete mathematics and cryptography, but still introduces core concepts and key terminology.

## Foundations

Zero-knowledge proofs (ZKPs) rely on discrete mathematics and cryptography. A **proof** is a mathematical demonstration that a statement is true. In ZKPs, this involves a **prover** (P) convincing a **verifier** (V) of the validity of a statement without revealing any underlying information. The **statement** refers to a claim about a mathematical relationship or property. A **witness** is a value or set of values that demonstrates the truth of the statement. 
The core principle of ZKPs is that they are **computationally zero-knowledge**, meaning that the verifier learns nothing beyond the validity of the statement, even if they have unlimited computational power. This is achieved through **probabilistic** methods, where the proof is repeated multiple times to minimize the probability of error. 
Key concepts include **completeness** (the prover can convince the verifier if the statement is true), **soundness** (the prover cannot convince the verifier if the statement is false), and **zero-knowledge** (the verifier learns nothing beyond the validity of the statement). ZKPs can be **interactive** (requiring multiple rounds of communication between prover and verifier) or **non-interactive** (where the prover sends a single proof to the verifier).

For instance, in a ZKP-based authentication system, a user can demonstrate knowledge of their password to a server without actually transmitting the password, thereby preventing password exposure in case of a server compromise.

In these systems, a user can prove that a transaction is valid (i.e., that they have the necessary funds) without revealing the transaction amount or the parties involved.

This has significant implications for fields such as finance, healthcare, and social science research, where collaborative analysis of sensitive data is often necessary.

## Common Errors

In the implementation and application of Zero Knowledge Proofs (ZKPs), several common errors can compromise the security and validity of the proof system. One mistake is incorrectly assuming that the zero-knowledge property implies perfect secrecy of the statement being proven. However, ZKPs only guarantee that no information about the witness (the private input) is revealed, not that the statement itself remains secret. Another error is failing to ensure the soundness property, which requires that a cheating prover cannot convince the verifier of a false statement. This can occur if the proof system's parameters are not properly set or if the cryptographic primitives used are insecure. Additionally, some practitioners may overlook the importance of the common reference string (CRS) in non-interactive ZKPs, which can lead to attacks if not properly generated or managed. A common pitfall in zk-SNARKs, a popular ZKP system, is miscalculating the curve parameters or the polynomial degrees, resulting in a loss of soundness or security. Lastly, neglecting to consider side-channel attacks, such as timing or power analysis attacks, can also compromise the security of ZKP implementations. These errors highlight the need for careful consideration of the underlying mathematics and cryptographic assumptions when designing and implementing ZKP systems.
