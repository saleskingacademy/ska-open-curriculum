# Formal Verification

> The course teaches core principles and mechanisms of formal verification, assuming some basic knowledge of computer science and mathematics.

## Foundations

Formal verification is based on mathematical proofs, utilizing a formal system to verify the correctness of a system, typically digital hardware or software. A formal system consists of a set of axioms, which are self-evident truths, and inference rules, which define how to derive new truths from existing ones. The vocabulary of formal verification includes terms such as specification, referring to a formal description of the desired behavior of a system, and implementation, denoting the actual system being verified. A formal model is a mathematical representation of a system, capturing its behavior and properties. The concept of correctness relates to the adherence of an implementation to its specification. A proof is a sequence of logical deductions, starting from axioms and using inference rules, to demonstrate the validity of a statement. Formal verification involves constructing a proof that an implementation satisfies its specification, utilizing various techniques, including model checking and theorem proving. Model checking is an automated method that exhaustively explores the state space of a system to verify its properties, whereas theorem proving relies on manual or automated construction of a proof, often using a formal calculus, such as propositional or predicate logic.

## Mechanisms

Formal verification in computer science involves a systematic approach to prove that a system, typically represented as a mathematical model, satisfies certain properties or specifications. The process works as follows: 
1. **Modeling**: The system to be verified is represented as a formal model, often using mathematical structures such as automata, Petri nets, or process algebras. 
2. **Specification**: The desired properties or behaviors of the system are formally specified using temporal logics, such as Linear Temporal Logic (LTL) or Computation Tree Logic (CTL). 
3. **Abstraction**: To reduce the complexity of the model, abstraction techniques are applied, which preserve the essential behaviors while eliminating irrelevant details. 
4. **Verification**: The formal model is then analyzed using verification algorithms, such as model checking or theorem proving, to determine whether the system satisfies the specified properties. 
5. **Counterexample Generation**: If the verification algorithm finds a violation of the specification, it generates a counterexample, which is a sequence of system states that demonstrates the property violation. 
6. **Refinement**: The system is refined by modifying its design or implementation to satisfy the properties, and the verification process is repeated until the system is proven correct. 
This iterative process ensures that the system meets its specifications, thereby guaranteeing its correctness and reliability. The choice of verification mechanism depends on the system's complexity, the specification's nature, and the desired level of assurance.

## Methods And Frameworks

Formal verification in computer science employs various methods and frameworks to ensure the correctness of software and hardware systems. Model Checking is a prominent method, which involves verifying a system's behavior against a set of properties using a model, such as a finite state machine. It is particularly useful for verifying concurrent and distributed systems, but may fail due to state space explosion.

Theorem Proving, on the other hand, uses mathematical formulas to prove the correctness of a system. It is often used for verifying cryptographic protocols and is effective when the system's behavior can be formally specified, but may fail if the specifications are incomplete or incorrect.

The B-Method and Z-notation are formal specification languages used to model and verify systems, particularly useful for verifying safety-critical systems. They provide a rigorous framework for specifying and verifying system behavior, but may fail if the specifications are ambiguous or inconsistent.

The Hoare Logic and Floyd-Hoare Method are used for verifying program correctness, providing a set of rules for reasoning about program behavior. They are effective for verifying sequential programs, but may fail if the program's behavior is highly concurrent or non-deterministic.

The CTL (Computation Tree Logic) and LTL (Linear Temporal Logic) formulas are used in model checking to specify temporal properties of a system, such as safety and liveness. They provide a formal framework for specifying and verifying system behavior over time, but may fail if the properties are not correctly formulated.

Each method and framework has its strengths and weaknesses, and the choice of which to use depends on the specific system being verified and the properties being checked.

## Common Errors

In formal verification, practitioners often make mistakes that can lead to incorrect or incomplete verification results. One common error is incomplete or inaccurate specification of the system's properties, which can result in false positives or false negatives. For instance, using a too-weak or too-strong invariant can cause the verification tool to miss errors or report spurious ones. Another mistake is neglecting to account for the system's environment and assumptions, leading to verification results that do not hold in practice. Additionally, incorrect usage of verification tools, such as misconfiguring the tool or misunderstanding its output, can also lead to errors. Furthermore, not considering the limitations and trade-offs of different verification techniques, such as model checking and theorem proving, can result in the application of an inappropriate technique for the problem at hand. These errors can be mitigated by carefully reviewing and testing the specifications, using multiple verification techniques, and considering the system's context and assumptions.
