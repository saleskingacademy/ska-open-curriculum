# Ar Vr Development

> The course teaches core concepts and principles of AR/VR development, assuming some basic knowledge of computer science terminology.

## Foundations

In the context of Computer Science, Augmented Reality (AR) and Virtual Reality (VR) development refer to the creation of immersive and interactive digital environments that alter or replace the real world. **Immersive** refers to the ability of a system to surround and engage the user, while **interactive** denotes the capacity for real-time user input and feedback. 
**Virtual Reality (VR)** is a computer-generated simulation of a three-dimensional environment that can be experienced and interacted with in a seemingly real or physical way. **Augmented Reality (AR)**, on the other hand, overlays digital information onto the real world, enhancing it with virtual objects, sounds, or other sensory inputs. 
Key concepts in AR/VR development include **Head-Mounted Displays (HMDs)**, which are wearable devices that provide an immersive experience, and **Tracking Systems**, which monitor the user's head or body movements to update the virtual environment accordingly. 
Understanding of **Computer Graphics**, **Human-Computer Interaction (HCI)**, and **3D Modeling** is essential for AR/VR development, as these disciplines provide the foundation for creating and rendering virtual objects and environments. 
Practitioners must also be familiar with **Programming Languages** such as C++, Java, or Python, and **Software Development Kits (SDKs)** like Unity or Unreal Engine, which provide the tools and frameworks for building AR/VR applications. 
A solid grasp of **Linear Algebra** and **Geometry** is necessary for tasks like **3D Transformations**, **Projections**, and **Collision Detection**, which are critical components of AR/VR development. 
Lastly, knowledge of **User Experience (UX) Design** principles is crucial for creating intuitive and engaging AR/VR experiences that meet user needs and expectations.

## Mechanisms

The development of Augmented Reality (AR) and Virtual Reality (VR) involves a complex interplay of hardware and software components. The causal chain begins with the user's input, which is typically provided through a controller, headset, or other device. This input is then processed by the system's software, which interprets the user's actions and translates them into virtual interactions. The software utilizes various algorithms, such as computer vision, machine learning, and physics engines, to generate a responsive and immersive experience. In AR, the system overlays virtual information onto the real world, using techniques like marker tracking, SLAM (Simultaneous Localization and Mapping), and object recognition. In VR, the system generates a completely virtual environment, using techniques like 3D modeling, texture mapping, and lighting simulation. The resulting virtual scene is then rendered onto a display device, such as a headset or screen, using graphics processing units (GPUs) and other hardware accelerators. The display device presents the virtual scene to the user, who perceives it as a realistic and interactive environment. Throughout this process, the system continuously tracks the user's head and body movements, using sensors like accelerometers, gyroscopes, and cameras, to ensure a seamless and responsive experience. The feedback loop between the user's input, the system's processing, and the resulting virtual scene is crucial to creating an immersive and engaging AR or VR experience.

## Methods And Frameworks

In AR/VR development, several methods and frameworks are employed to create immersive experiences. The Model-View-Controller (MVC) pattern is commonly used to separate concerns and manage complexity. The Unity game engine utilizes a variant of MVC, where the Model represents data, View handles rendering, and Controller manages user input. 
The Scene-Graph model is used to manage 3D scenes, where objects are organized in a hierarchical structure, facilitating efficient rendering and collision detection. 
The Render Pipeline is a framework for managing the rendering process, involving stages such as vertex processing, pixel shading, and compositing. 
The Physically-Based Rendering (PBR) formula is used to simulate real-world lighting, where the Bidirectional Reflectance Distribution Function (BRDF) models the way light interacts with materials. 
When to use: MVC for complex applications, Scene-Graph for 3D scenes, Render Pipeline for custom rendering, and PBR for realistic lighting. 
Failure modes: MVC can lead to tight coupling if not implemented correctly, Scene-Graph can result in deep recursion if not optimized, Render Pipeline can cause performance issues if not properly configured, and PBR can be computationally expensive if not used judiciously. 
Additionally, the ARKit and ARCore frameworks provide methods for building augmented reality experiences, utilizing techniques such as marker tracking, plane detection, and light estimation. 
When to use: ARKit for iOS devices, ARCore for Android devices. 
Failure modes: ARKit and ARCore can be sensitive to environmental factors, such as lighting and occlusion, and may require careful calibration and testing to ensure robust performance.

## Worked Examples

To illustrate key concepts in AR/VR development, consider the following examples. 
1. Calculating Field of View (FOV): Given a VR headset with a horizontal FOV of 100 degrees and a vertical FOV of 80 degrees, and a screen resolution of 1832 x 1920 pixels, calculate the number of pixels per degree. 
Horizontal pixels per degree = 1832 pixels / 100 degrees = 18.32 pixels/degree. 
Vertical pixels per degree = 1920 pixels / 80 degrees = 24 pixels/degree. 
2. Estimating Tracking System Latency: A VR system uses an outside-in tracking system with 6 cameras, each capturing images at 100 Hz. If the processing time for each image is 5 ms, and the system requires 3 images to determine the headset's position, calculate the total latency. 
Latency = (3 images / 100 Hz) + (3 images * 5 ms) = 30 ms + 15 ms = 45 ms. 
3. Optimizing 3D Model Rendering: An AR application renders a 3D model with 10,000 vertices and 20,000 triangles. If the graphics processing unit (GPU) can render 1 million vertices per second, calculate the rendering time per frame at 60 Hz. 
Rendering time per frame = (10,000 vertices / 1,000,000 vertices/second) = 0.01 seconds. 
At 60 Hz, the GPU must render a frame every 1/60 seconds = 0.0167 seconds, which is greater than the rendering time, indicating the GPU can handle the model at 60 Hz.

## Common Errors

In AR/VR development, practitioners often make mistakes that can lead to poor user experience, performance issues, or even motion sickness. One common error is incorrect handling of latency, which can cause synchronization issues between the user's head movements and the virtual environment. This can be due to inadequate optimization of rendering pipelines or failure to account for system latency. Another mistake is neglecting to consider the field of view (FOV) and IPD (inter-pupillary distance) of the user, leading to incorrect stereoscopic rendering and potential eye strain. Additionally, developers may overlook the importance of proper lighting and shading in virtual environments, resulting in unrealistic and uncomfortable visuals. Incorrect usage of tracking systems, such as inside-out or outside-in tracking, can also lead to inaccurate pose estimation and poor user experience. Furthermore, practitioners may fail to account for user comfort and safety, neglecting to implement features such as comfort mode or providing inadequate warnings for potentially disturbing content. These errors can be mitigated by following best practices, conducting thorough user testing, and staying up-to-date with the latest research and guidelines in AR/VR development.
