# Parallel Computing

> The course teaches core concepts and principles of parallel computing, assuming some basic knowledge of computing terminology.

## Foundations

In parallel computing, a **parallel system** is a computer system that consists of multiple **processing units** (PUs), also known as **processors** or **cores**, which can execute multiple **instructions** simultaneously, increasing overall processing power and reducing execution time. A **parallel program** is a program designed to take advantage of multiple PUs by dividing its workload into smaller, independent **tasks** that can be executed concurrently. **Concurrency** refers to the ability of a program to perform multiple tasks simultaneously, while **parallelism** specifically refers to the use of multiple PUs to achieve concurrency. A **thread** is a separate flow of execution within a program, and **multithreading** is a technique where multiple threads are used to achieve concurrency. **Synchronization** refers to the coordination of access to shared resources among multiple threads or PUs to prevent conflicts and ensure data consistency. **Scalability** is the ability of a parallel system to increase its performance as the number of PUs increases. Key concepts in parallel computing include **speedup**, which measures the performance gain of a parallel program over its sequential counterpart, and **efficiency**, which measures the ratio of actual speedup to theoretical maximum speedup. Understanding these core definitions and principles is essential for designing and developing effective parallel computing systems.

In parallel computing, a **computing system** is defined as a collection of processing units, memory, and interconnects that work together to execute computational tasks. The core concept of parallel computing is to divide a task into smaller sub-tasks, called **threads** or **processes**, which can be executed simultaneously by multiple processing units, increasing overall processing speed. A **processing unit** is a component that performs computations, such as a central processing unit (CPU) or graphics processing unit (GPU). **Concurrency** refers to the ability of a system to execute multiple threads or processes simultaneously, while **parallelism** specifically refers to the simultaneous execution of threads or processes on multiple processing units. **Synchronization** is the coordination of threads or processes to ensure correct execution and avoid conflicts, using techniques such as **locks**, **semaphores**, or **barriers**. **Scalability** is the ability of a parallel system to increase performance as more processing units are added, with **strong scaling** referring to the ability to solve a fixed-size problem in less time, and **weak scaling** referring to the ability to solve larger problems in the same time. **Parallel algorithms** are designed to take advantage of multiple processing units, using techniques such as **data parallelism**, **task parallelism**, or **pipelining**. Understanding these fundamental concepts and vocabulary is essential for designing and implementing efficient parallel computing systems.

## Mechanisms

Parallel computing operates by dividing tasks into smaller sub-tasks that can be executed simultaneously by multiple processing units, such as cores or processors. The causal chain begins with the decomposition of the problem into independent or interdependent tasks, which are then allocated to available processing units. Each processing unit executes its assigned task, accessing shared memory or communicating with other units as necessary. Synchronization mechanisms, such as locks or barriers, ensure that tasks are executed in a coordinated manner, preventing data inconsistencies or race conditions. Data parallelism is achieved through the distribution of data across multiple processing units, allowing each unit to operate on a portion of the data. Task parallelism, on the other hand, involves the execution of multiple tasks concurrently, each processing a separate portion of the data or performing a distinct function. The results from each processing unit are then combined, using techniques such as reduction or aggregation, to produce the final output. This process is managed by a runtime environment or parallel programming framework, which handles task scheduling, resource allocation, and communication between processing units. By leveraging multiple processing units, parallel computing can significantly reduce the execution time of computationally intensive tasks, improving overall system performance and efficiency. This decomposition is typically achieved through algorithms designed to take advantage of parallel processing.

The next step involves the allocation of these tasks to available processing units, a process managed by the operating system or a parallel computing framework. This allocation considers factors such as the number of available processors, the computational load of each task, and the need for communication between tasks.

Once tasks are allocated, the processing units execute them concurrently. This concurrent execution is the core of parallel computing, enabling the reduction of overall processing time by leveraging multiple processing units.

For tasks that are interdependent, synchronization mechanisms are employed to coordinate the execution of tasks and ensure data consistency. These mechanisms include barriers, semaphores, and monitors, which regulate the access to shared resources and enforce the correct order of operations.

Data distribution and collection are also critical mechanisms in parallel computing. Data parallelism, where the same operation is applied to different data elements, is facilitated by distributing the data across processing units. After processing, the results may need to be collected and combined, a step that can be as simple as summing results or as complex as performing a distributed sorting algorithm.

The final step in the causal chain is the combination of results from the parallel tasks to produce the final output. This step can involve aggregation operations, such as summing or averaging, or more complex operations like merging sorted lists. The outcome is a solution that is produced more quickly than if the tasks were executed sequentially, leveraging the power of parallel computing to solve complex computational problems efficiently.

## Methods And Frameworks

Parallel computing employs various methods and frameworks to achieve efficient execution of concurrent tasks. The Master-Slave model is suitable for tasks with a single control point, where one process (master) distributes tasks to multiple slave processes. In contrast, the Peer-to-Peer model is used when all processes have equal status and can initiate communication. The Data Parallelism method is applied when the same operation is performed on large datasets, whereas Task Parallelism is used when multiple tasks are executed concurrently. The MPI (Message Passing Interface) framework is commonly used for distributed-memory architectures, while OpenMP is used for shared-memory architectures. Amdahl's Law (1/(1-P + P/S)) calculates the maximum theoretical speedup of a parallel program, where P is the fraction of parallelizable code and S is the number of processors. Failure modes include synchronization overhead, communication latency, and load imbalance, which can lead to decreased performance and efficiency.

The Message Passing Interface (MPI) framework is widely used for distributed-memory architectures, providing a standardized protocol for inter-process communication. The OpenMP framework is used for shared-memory architectures, providing a set of directives and APIs for parallelizing loops and tasks.

Amdahl's Law, which states that the maximum theoretical speedup is limited by the fraction of the program that cannot be parallelized, is used to predict the performance of parallel algorithms. Gustafson's Law, which states that the size of the problem can be increased to fully utilize the available processing power, is used to analyze the scalability of parallel systems.

The failure modes of parallel computing include synchronization overhead, communication overhead, and load imbalance, which can lead to decreased performance and increased execution time. Understanding these methods, frameworks, and formulas is crucial for designing and optimizing parallel computing systems.

## Worked Examples

To illustrate the principles of parallel computing, consider the following examples. 
1. **Speedup Calculation**: Suppose we have a program that takes 100 seconds to execute on a single processor. When executed on a 4-processor parallel system, the execution time reduces to 30 seconds. The speedup achieved is calculated as the ratio of the sequential execution time to the parallel execution time: Speedup = 100 / 30 = 3.33. This indicates that the parallel system is 3.33 times faster than the sequential system.
2. **Amdahl's Law**: A program has a parallelizable fraction of 0.8 and a non-parallelizable fraction of 0.2. If the parallelizable fraction is executed on 8 processors, the speedup of the parallelizable fraction is 8. Using Amdahl's Law, the overall speedup is calculated as: 1 / (0.2 + 0.8 / 8) = 1 / (0.2 + 0.1) = 1 / 0.3 = 3.33. This demonstrates the limitations of parallel processing due to the non-parallelizable fraction.
3. **Parallel Matrix Multiplication**: Consider two 1000x1000 matrices, A and B, to be multiplied on a 4-processor parallel system. The matrix multiplication can be divided into four equal sub-tasks, each executed on a separate processor. Assuming each processor performs 250,000,000 floating-point operations per second, and the matrix multiplication requires 2,000,000,000 operations, the parallel execution time is: 2,000,000,000 / (4 * 250,000,000) = 2 seconds. In contrast, the sequential execution time would be: 2,000,000,000 / 250,000,000 = 8 seconds, demonstrating a speedup of 4. **Amdahl's Law**: A program consists of 80% parallelizable code and 20% sequential code. If we run this program on a 10-processor parallel system, what is the maximum theoretical speedup? This shows that even with a large number of processors, the sequential portion of the code limits the overall speedup.
3. **Parallel Efficiency**: A parallel algorithm has a total workload of 1000 units and is executed on a 5-processor system. The parallel efficiency is given by the formula: Efficiency = (Actual Speedup) / (Number of Processors). If the actual speedup achieved is 4, then the efficiency is 4 / 5 = 0.8 or 80%. ## Applications

Parallel computing has numerous applications in various domains, including scientific simulations, data analytics, machine learning, and computer-aided design. In scientific simulations, parallel computing is used to solve complex problems such as weather forecasting, fluid dynamics, and materials science. For instance, the Weather Research and Forecasting (WRF) model uses parallel computing to simulate weather patterns and predict future weather conditions. In data analytics, parallel computing is used to process large datasets in parallel, enabling faster data processing and analysis. The MapReduce programming model, used in Hadoop, is a widely used parallel computing framework for data analytics. In machine learning, parallel computing is used to speed up the training of machine learning models, such as neural networks and decision trees. Computer-aided design (CAD) software also utilizes parallel computing to perform complex simulations and analysis, such as finite element analysis and computational fluid dynamics. Additionally, parallel computing is used in cryptography, genome assembly, and computer graphics, among other fields. The key principle behind these applications is the ability to divide a complex problem into smaller sub-problems that can be solved concurrently, resulting in significant speedup and improved productivity.

## Common Errors

In parallel computing, practitioners often make mistakes that can significantly impact the performance, scalability, and correctness of their applications. One common error is incorrect synchronization, where shared resources are accessed without proper locking or barriers, leading to data races and inconsistent results. Another mistake is insufficient parallelism, where the parallelizable work is not adequately divided among processing units, resulting in underutilization of resources and poor speedup. 
Load imbalance is also a prevalent issue, where some processing units are assigned disproportionately more work than others, causing idle times and reducing overall efficiency. Furthermore, many practitioners neglect to consider the overhead of communication and data transfer between processing units, which can dominate the execution time and negate the benefits of parallelization. 
Additionally, some developers fail to account for the differences in execution order and timing between sequential and parallel executions, leading to non-deterministic behavior and bugs that are difficult to reproduce and debug. 
These errors often arise from a lack of understanding of the underlying parallel computing models, such as data parallelism, task parallelism, and pipeline parallelism, and the specific challenges and constraints associated with each model.

## Advanced

In parallel computing, advanced research focuses on optimizing performance, scalability, and energy efficiency. One key area is heterogeneous parallelism, which involves combining different types of processing units, such as CPUs, GPUs, and FPGAs, to leverage their respective strengths. This requires developing new programming models, such as OpenCL and CUDA, that can efficiently manage and schedule computations across diverse architectures. Another important direction is parallelizing irregular applications, which exhibit non-uniform memory access patterns and require novel data structures and algorithms to achieve efficient parallelization. Researchers are also exploring new parallel programming paradigms, such as task-based parallelism and parallel graph processing, to tackle complex problems in domains like machine learning, scientific simulations, and data analytics. Open questions include developing effective methods for parallelizing legacy serial code, optimizing parallel algorithms for emerging architectures like quantum computing and neuromorphic computing, and ensuring the reliability and fault tolerance of large-scale parallel systems. The field is moving towards greater emphasis on autonomous and adaptive parallel systems, which can self-configure and self-optimize to achieve optimal performance and energy efficiency in response to changing workloads and operating conditions.

Open questions in the field include the development of efficient parallel algorithms for sparse matrix operations, parallelizing dynamic programming algorithms, and optimizing parallelism for emerging architectures such as GPUs and FPGAs. The field is moving towards heterogeneous parallel computing, where different types of processors and accelerators are integrated to achieve optimal performance. Researchers are also exploring parallel computing for emerging applications such as artificial intelligence, data science, and scientific simulations. Key areas of research include parallel programming models, parallel runtime systems, and parallel performance modeling and analysis. Furthermore, the increasing importance of energy efficiency and power consumption in parallel computing systems is driving research in green parallel computing and low-power parallel architectures.
