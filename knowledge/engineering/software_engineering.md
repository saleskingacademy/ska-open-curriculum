# Software Engineering

> The course assumes foundational knowledge and covers specialisation within the field, including analysis and competing approaches to software engineering.

## Foundations

Software engineering is the disciplined, systematic application of engineering principles to the design, development, maintenance, testing, and evaluation of software. It aims to produce software that is reliable, efficient, maintainable, and meets user requirements within constraints of cost and time. At its core, software engineering rests on first principles: modularity, abstraction, encapsulation, separation of concerns, and rigorous verification. It treats software as an engineered artifact, subject to lifecycle models, quality metrics, and process improvement frameworks. The foundational challenge is managing complexity through decomposition and formalization, ensuring correctness via specification and validation, and optimizing resource allocation through project management techniques.

In software engineering, a **software system** refers to a collection of **software components**, which are executable instructions that perform specific tasks, interacting with each other to achieve a common goal. **Software engineering** itself is the application of **engineering principles** and techniques to the design, development, testing, and maintenance of software systems. A **software process** is a set of activities, methods, and practices used to develop and maintain software systems. Key **software engineering principles** include **abstraction**, which involves hiding implementation details to focus on essential features, and **modularity**, which involves breaking down a system into smaller, independent components. **Requirements engineering** is the process of defining, analyzing, and documenting the requirements of a software system, while **software design** involves creating a detailed plan for the structure and behavior of the system. **Software quality** refers to the degree to which a software system meets its specifications, is reliable, and performs its intended functions. Understanding these core concepts and their relationships is essential for software engineering practitioners.

Understanding these core definitions and principles is essential for effective software engineering practice.

## Requirements Engineering

Requirements Engineering is the systematic process of eliciting, specifying, analyzing, validating, and managing software requirements. The Volere Requirements Specification Template (Robertson & Robertson, 1999) structures requirements into functional, non-functional, and domain requirements. Key steps include:  
1. Stakeholder identification and analysis (Rational Unified Process - RUP)  
2. Elicitation techniques: interviews, use case modeling (Jacobson’s Use Case 9-step method), and scenario analysis  
3. Specification using formal languages (Z notation, Alloy) or semi-formal models (UML Use Case Diagrams)  
4. Validation via reviews, prototyping, and traceability matrices (ISO/IEC/IEEE 29148)  
5. Change management with version control and impact analysis  
Effective requirements engineering reduces defects by up to 50% per studies by Boehm and Basili (1981).

## Software Architecture

Software Architecture defines the high-level structure of a system, its components, their interactions, and patterns guiding design decisions. The 4+1 View Model (Kruchten, 1995) partitions architecture into:  
- Logical view (class and object diagrams)  
- Development view (component and module organization)  
- Process view (concurrency and communication)  
- Physical view (deployment topology)  
- Scenarios (use cases driving architecture validation)  
Architectural styles include Layered (OS layered stacks), Client-Server, Microservices (bounded contexts, RESTful APIs), Event-Driven (publish-subscribe), and Pipe-and-Filter. The Attribute-Driven Design (ADD) method (Bass, Clements, Kazman) guides iterative architecture derivation based on quality attribute requirements (performance, modifiability, security). Architectural decisions are documented using ADRs (Architecture Decision Records).

## Agile Methodologies

Agile software engineering emphasizes iterative development, customer collaboration, and responsiveness to change. Scrum (Schwaber & Sutherland, 1995) is a dominant framework with:  
- Roles: Product Owner, Scrum Master, Development Team  
- Artifacts: Product Backlog, Sprint Backlog, Increment  
- Events: Sprint Planning, Daily Scrum (15 min), Sprint Review, Sprint Retrospective  
Sprints typically last 2-4 weeks, delivering potentially shippable increments. Kanban focuses on continuous flow with Work-In-Progress (WIP) limits and cycle time metrics. Extreme Programming (XP) prescribes practices like pair programming, test-driven development (TDD), continuous integration, and refactoring. Empirical data shows Agile teams improve delivery frequency by 30-50% and defect rates decrease by 40%.

## Software Testing & Verification

Testing ensures software correctness and quality. The V-Model aligns testing phases to development stages:  
- Unit Testing (JUnit, NUnit): tests individual functions/methods, coverage metrics (statement, branch >80%)  
- Integration Testing: validates module interactions, using top-down, bottom-up, or sandwich approaches  
- System Testing: end-to-end validation against requirements, including functional and non-functional tests  
- Acceptance Testing: user validation, often automated via Cucumber or Selenium  
Formal verification uses model checking (SPIN, NuSMV) and theorem proving (Coq, Isabelle) to mathematically prove correctness. Mutation testing (e.g., PIT for Java) assesses test suite robustness by injecting faults. Continuous Integration (CI) pipelines automate testing and enforce quality gates.

## Configuration Management & Devops

Configuration Management controls software artifacts and environments to ensure reproducibility and traceability. Git (Linus Torvalds, 2005) is the de facto version control system, using SHA-1 hashes for commits, branching, and merging. Semantic Versioning (SemVer 2.0.0) prescribes MAJOR.MINOR.PATCH increments to communicate compatibility. DevOps integrates development and operations to accelerate delivery and improve reliability:  
- Infrastructure as Code (IaC) with Terraform, Ansible  
- Continuous Integration/Continuous Deployment (CI/CD) pipelines using Jenkins, GitLab CI, or GitHub Actions  
- Monitoring and feedback loops with Prometheus, ELK stack  
Metrics like Mean Time to Recovery (MTTR) and Deployment Frequency quantify DevOps performance (DORA metrics).

## Software Maintenance & Evolution

Maintenance consumes up to 60-80% of software lifecycle costs. Lehman’s Laws of Software Evolution (1974) describe software as a continuously evolving entity requiring ongoing adaptation. Maintenance types: corrective, adaptive, perfective, and preventive. The Spiral Model (Boehm, 1986) incorporates iterative risk analysis for evolution. Refactoring catalogs (Fowler, 1999) provide 72 patterns to improve code structure without altering behavior, enhancing maintainability. Software metrics such as cyclomatic complexity (McCabe, 1976) and code churn inform maintainability assessments.

## Mechanisms

Software engineering mechanisms involve a series of steps and processes that enable the development, maintenance, and evolution of software systems. The causal chain begins with requirements gathering, where stakeholders' needs are collected and analyzed to define the software's functional and non-functional requirements. This leads to the creation of a software design, which outlines the architecture, components, and interfaces of the system. The design is then implemented through coding, where programmers write the source code in a chosen programming language.

The source code is subsequently tested through various levels of testing, including unit testing, integration testing, and system testing, to ensure it meets the requirements and works as expected. Testing reveals defects, which are then fixed through debugging and defect repair. The updated code is then integrated into the larger system, and the testing process is repeated to ensure the changes have not introduced new defects.

This iterative process continues until the software meets the required quality and functionality standards. Once the software is deployed, it enters the maintenance phase, where it is continuously monitored and updated to fix defects, address new requirements, and adapt to changing environments. Throughout this process, software engineering mechanisms rely on a range of tools, techniques, and methodologies, such as version control systems, agile development frameworks, and testing frameworks, to manage the complexity and ensure the quality of the software system.

Throughout these stages, various software engineering techniques are applied, such as version control, continuous integration, and agile methodologies, to manage the development process and ensure the delivery of high-quality software. Each stage has a direct impact on the subsequent stage, and defects or errors in one stage can propagate to subsequent stages, emphasizing the importance of rigorous testing and validation.

## Methods And Frameworks

In software engineering, various methods and frameworks are employed to guide the development process. The Waterfall model is a linear approach, suitable for projects with well-defined requirements and minimal changes expected. Its failure mode is rigidity, making it unsuitable for projects with evolving requirements. The Agile methodology, including Scrum and Kanban, is iterative and incremental, ideal for projects with changing requirements. Its failure mode is lack of discipline, leading to scope creep and decreased productivity. The V-Model is a verification and validation approach, ensuring that each phase is thoroughly tested before proceeding. Its failure mode is overemphasis on documentation, potentially slowing down the development process. The Spiral model combines elements of iterative development and the Waterfall model, suitable for high-risk projects. Its failure mode is increased complexity, making it challenging to manage. The Unified Process (UP) is a framework that provides a structured approach to software development, emphasizing iterative and incremental development. Its failure mode is overengineering, resulting in unnecessary complexity. The Capability Maturity Model (CMM) is a framework for evaluating the maturity of an organization's software development processes, providing a guideline for improvement. Its failure mode is overreliance on documentation, potentially neglecting actual process improvement.

## Worked Examples

To illustrate key concepts in software engineering, consider the following examples. 
1. **Estimating Project Duration**: A software development team is tasked with creating a web application. The team estimates that the project requires 1000 lines of code. Assuming an average developer productivity of 200 lines of code per week, and a team of 5 developers, the total project duration can be estimated as follows: Total lines of code / (Developer productivity * Number of developers) = 1000 / (200 * 5) = 1 week. 
2. **Calculating Return on Investment (ROI)**: A company invests $100,000 in a software project that is expected to generate $200,000 in revenue. The ROI can be calculated as: (Gain from investment - Cost of investment) / Cost of investment = ($200,000 - $100,000) / $100,000 = 100%. 
3. **Determining Test Coverage**: A software testing team has written 50 test cases to cover 1000 lines of code. If each test case covers 20 lines of code, the test coverage can be calculated as: (Number of test cases * Lines of code covered per test case) / Total lines of code = (50 * 20) / 1000 = 1 or 100%.

## Common Errors

In software engineering, common errors occur due to inadequate design, insufficient testing, and poor implementation. One mistake is the God Object anti-pattern, where a single class or module has too many responsibilities, leading to tight coupling and low cohesion. Another error is the use of magic numbers, which are numerical values used in code without explanation, making maintenance and debugging difficult. Insufficient error handling is also a common issue, where developers fail to anticipate and handle potential exceptions, resulting in system crashes or unexpected behavior. Additionally, ignoring the principles of separation of concerns and the single responsibility principle can lead to complex, hard-to-maintain code. Furthermore, not following a consistent naming convention and not using comments to explain code can make it difficult for other developers to understand the codebase. These errors can be mitigated by following established software engineering principles, such as the SOLID principles, and by using design patterns and testing methodologies to ensure robust and maintainable software systems.

In software engineering, common errors include inadequate requirements gathering, insufficient testing, and poor design. Insufficient testing can cause bugs and errors to go undetected, ultimately affecting the software's reliability and quality. Poor design can lead to maintainability issues, making it difficult to modify or update the software. Additionally, errors such as tight coupling and low cohesion in object-oriented design can make software rigid and prone to breakage. Furthermore, neglecting to follow established software development methodologies and failing to properly document code can lead to disorganization and difficulties in maintenance. These errors often stem from inadequate planning, poor communication, and lack of adherence to software engineering principles. By understanding these common errors, practitioners can take proactive measures to avoid them, ensuring the development of high-quality software that meets user needs and is maintainable over time.

## Advanced

In software engineering, advanced topics delve into the complexities of large-scale system development, human-computer interaction, and the integration of artificial intelligence and machine learning. Graduate-level studies explore the theoretical foundations of software engineering, including formal methods, such as model checking and theorem proving, to ensure system correctness and reliability. Open questions in the field include the development of scalable and maintainable architectures for complex systems, the integration of security and privacy by design, and the application of empirical software engineering methods to improve software development processes. The field is moving towards the adoption of agile and lean methodologies, DevOps practices, and the use of cloud computing and containerization to support rapid deployment and continuous integration. Additionally, there is a growing interest in the application of software engineering principles to emerging domains, such as the Internet of Things, cybersecurity, and data science. Researchers are also exploring new paradigms, including aspect-oriented software development, service-oriented architecture, and model-driven engineering, to address the challenges of complex system development. Furthermore, the increasing use of open-source software and the rise of inner-source development are changing the way software is developed, shared, and maintained, raising new questions about licensing, governance, and community engagement.
